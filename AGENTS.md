# Instructions for future project sessions

1. Read `README.md` completely, then `PROMPT.md`, before making any project change. Treat the charter, Core Values, and active evidence state there as required context.
2. Check `git status`, data restore/audit receipts, and the newest holdout receipt before repeating any experiment. Do not rerun work just because prior-session notes are available; inspect the workspace first.
3. Keep organizer scores, owner-reported scores, model projections, and local holdout measurements clearly attributed. A public/blocked score is not a private or final score.
4. Do not use the DrivenData leaderboard except as permitted by its current Terms of Use. No automated or manual monitoring/copying without prior written permission or an authorized API.
5. Preserve preregistration and stop rules. Do not alter a failed candidate's gate after seeing its scores. A failed candidate must not become a download or submission.
6. Never use a prior submission raster as the candidate score surface or copy/rename it. Compare candidate pixels to relevant prior artifacts before making any new raster downloadable.
7. Before release or PR, perform the three review passes specified in `PROMPT.md` and update the receipts, README status, site, and PR claims so every statement is verifiable.
